Uso de IA

para Desenvolvimento de MVP

Boas práticas, definição de escopo e segurança — sem cair no vibecoding

PEI V · Prof.: Diego Ramos Inácio

Um MVP gerado numa tarde 🚨

  • Funciona perfeitamente na demo...
  • ...mas quebra no primeiro teste com usuário real
  • Tem senha/chave de API exposta direto no código
  • O próprio aluno não consegue explicar o que o código faz na banca

Isso é vibecoding: aceitar o que a IA gera sem entender, sem revisar, sem conseguir defender.

O que é "vibecoding"? 💭

  • Pedir código para a IA e aceitar sem ler
  • Não saber explicar por que o código funciona (ou se funciona)
  • Deixar a IA decidir o escopo do projeto, não só a implementação
  • Confundir "a demo rodou" com "o problema foi resolvido"

Regra prática: "Se eu não consigo explicar em 2 frases o que esse código faz e por que, eu não comito."

Por que isso compromete sua nota ⚠️

Critérios de avaliação do PEI V
"Alterações geradas automaticamente" e "participação apenas declarada, sem evidência verificável" NÃO contam como participação individual.
  • A nota é por autoria comprovada: commits, PRs, revisões, correções após feedback
  • Quem não entende o próprio PR não consegue defendê-lo numa Issue de avaliação nem na banca
  • Commit pequeno e compreensível vale mais que vários commits gerados em bloco

Definir o que é importante antes do prompt 🎯

1 Volte ao problema validado com os 3 usuários reais (etapa 1 do plano de trabalho). A IA não conhece o problema, só o que você escreve.
2 Use MoSCoW (Must / Should / Could / Won't) sobre o Lean Canvas da etapa 2 para priorizar.
3 Regra: MVP = a menor coisa que testa a hipótese, não a maior coisa que a IA consegue gerar.

Boas práticas no uso de IA 📝

  • Prompt com contexto real: problema, público, stack — nunca genérico
  • Ler linha a linha todo código gerado antes de aceitar
  • Pedir à IA para explicar o próprio código que gerou — teste de entendimento
  • Comitar em pedaços pequenos e compreensíveis
  • Usar IA também para gerar testes e casos de borda, não só features
  • Checar se bibliotecas sugeridas existem de fato e são mantidas (IA alucina nomes de pacotes)

Feature, teste e caso de borda 🧩

Feature: validar se alguém pode se cadastrar no sistema (idade mínima de 16 anos).

def pode_cadastrar(idade):
    return idade >= 16
A IA gera isso fácil — é só a feature, ainda sem nenhum teste
def test_maior_de_idade_pode_cadastrar():
    assert pode_cadastrar(20) == True
Teste comum: confirma o caminho esperado
def test_idade_negativa():
    assert pode_cadastrar(-1) == False
Caso de borda: entrada inválida que a regra simples não trata explicitamente — exatamente o tipo de furo que aparece quando um usuário real digita algo inesperado

Pedir só a feature para a IA não é suficiente: peça também os testes e os casos de borda.

Segurança básica para o MVP 🔒

.gitignore + variáveis de ambiente
Nunca commitar senha, token ou API key
Validação de entrada
Todo dado vindo de formulário/usuário deve ser validado
HTTPS + autenticação mínima decente
Nunca implementar hash de senha "na mão"
"Revise a segurança deste código"
Pedir isso à IA é uma prática válida e barata — use-a também para revisar, não só gerar

Ranking de IAs gratuitas: como comparar de verdade 📊

  • Benchmarks (SWE-bench, Artificial Analysis) mudam mês a mês
  • Blogs agregadores costumam citar números desatualizados ou de metodologias diferentes
  • Regra: não confie em ranking de blog, confie na fonte oficial — o mesmo princípio vale para código gerado por IA

Ferramentas gratuitas — configuração básica ⚙️

Ferramenta Acesso gratuito Configuração básica
Claude.ai / ChatGPT (free) Chat web, modelos menores do catálogo Pensar arquitetura/prompt antes de gerar código; revisar manualmente
GitHub Copilot Free Extensão no VS Code, cota limitada Login com conta GitHub; nunca deixar token em arquivo versionado
Gemini (CLI / AI Studio) API com cota diária gratuita API key sempre em variável de ambiente, nunca hardcoded
Cursor (free tier) Editor próprio, cota de requisições Arquivo .cursorrules no projeto com contexto fixo do MVP
DeepSeek (free) Chat web / API barata Boa p/ iteração rápida — sempre revisar antes de aceitar
Ollama (modelo local) 100% gratuito, roda na máquina Opção offline — zero risco de vazar dado sensível do projeto

"Gratuito" sempre tem uma troca: cota, modelo mais fraco, ou seus dados/prompts usados para treinar o próximo modelo. Nunca cole dado sensível de usuário real da comunidade atendida pelo projeto de extensão em ferramenta gratuita sem checar a política de privacidade.

Atividade prática 🧪

1 Em grupo, peguem um trecho real do próprio MVP e gerem uma função com IA.
2 Apliquem o checklist de revisão (entendimento + segurança) antes de aceitar.
3 Justifiquem por escrito, no formato de Issue usado na disciplina, por que aceitaram ou rejeitaram o código.

Conclusão

IA é uma ferramenta poderosa para construir o MVP mais rápido — desde que você mantenha o controle do escopo, do entendimento e da segurança.

  • Defina o essencial antes de abrir o prompt
  • Revise e entenda tudo que a IA gerar
  • Nunca exponha segredo nem dado sensível de usuário
  • Confirme ranking e limites em fontes oficiais, não em blogs
